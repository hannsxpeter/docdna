# Changelog

All notable changes to docdna are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [1.3.0] - 2026-08-19

### Added

- **Advisory prose review is now part of Check.** The new `prose` pass reports vague attributions,
  filler, chatbot phrases, promotional terms, ornate substitutes for `is`, formulaic contrasts,
  generic endings, and likely title-case headings. It ignores frontmatter, literal code, HTML comments,
  and link destinations. Findings never gate, the pass never rewrites a document, and it makes no claim
  about whether a person or model wrote the text.
- **Backfill now has a constrained prose audit after evidence verification.** The new
  `references/prose.md` permits shorter and clearer wording while preserving every fact, citation,
  identifier, command, number, table relationship, frontmatter value, and GAP. Any edit is verified
  again. The guidance is adapted from pstack's `unslop` skill under the MIT notice committed with it.
- **Deterministic Unicode hygiene is now part of Check.** The new `hygiene` pass reports exact paths,
  lines, columns, codepoints, Unicode names, and classes for invisible format characters and space
  lookalikes in repository documentation. Terminal controls, bidirectional controls, and Unicode tag characters gate at the
  default `major` threshold; lower-risk findings warn unless `--fail-on minor` is selected. Legitimate
  emoji ZWJ, VS15, and VS16 sequences are preserved. Exact totals remain available while detailed rows
  cap at 1,000 to bound report memory. Its Unicode classes and emoji-glue handling are
  adapted from `watermarks-remover` 0.4.0 under the MIT license recorded in
  `skill/references/third-party-notices.md`.

### Changed

- **Generated human-facing text is cleaned before its existing race-safe write.** `DOCDNA.md`, `llms.txt`,
  its sidecar prose, and regenerated gap summaries strip suspicious format controls and normalize exotic
  spaces. Manifest JSON and user-authored documents are never rewritten by this pass. Statistical
  token-sampling watermarks, file-container metadata, media marks, and human-authorship claims remain out
  of scope.

## [1.2.1] - 2026-08-05

### Fixed

- **Agent-facing indexes no longer copy repository prose.** `llms.txt` uses trusted catalog titles,
  static state notes, and encoded repository-relative paths. A document or edited manifest cannot move
  instruction-like text into the generated agent index.
- **Unsafe control files and stale imported scans now fail closed.** A symlinked, hardlinked, or otherwise
  unsafe `.docdna/config.json` stops selection and checking. Imported scans are reproduced against a fresh
  repository fingerprint before their results are used.
- **Exceptional writes and inputs leave a consistent boundary.** Deeply nested repository JSON is ignored
  without a traceback, both selector outputs are preflighted before either is written, the human report is
  written before the authoritative manifest, and atomic replacement syncs the containing directory.
- **Release inputs are immutable.** CI actions are pinned to reviewed commits with read-only repository
  permissions, and installation examples select the v1.2.1 tag instead of the mutable default branch.

### Changed

- **Repository access now requires a POSIX host with descriptor-relative, no-follow filesystem
  support.** Control files and imported scans are size-bounded and shape-validated, repository roots
  stay bound to one inode across each operation, Git-derived scan data is checked against that binding,
  filesystem walks do not follow swapped directories or block on special files, and stub deletion
  revalidates the exact content it removes. Atomic output replacement preserves existing file modes.
- **The prose documentation is rewritten and layered.** `README.md` was written for a reader who already
  knew what a selection engine was, and it opened on the mechanism rather than on the question a newcomer
  actually arrives with. It now leads with "which documents does this project actually owe", says who the
  tool is for in plain language, and annotates the two real output samples line by line instead of assuming
  the reader can parse them. Nothing was softened: the measured drift precision, the unadjudicated state of
  selection, and the tripwire claim held open all survive, in shorter form, each linking to the page that
  carries the full argument.
- **Four documentation pages added**, holding the depth the README used to carry inline:
  `docs/QUICKSTART.md` (a guided first run and a glossary of every term the report uses),
  `docs/HOW-IT-DECIDES.md` (the selection engine, the eight questions, the catalog, the invariants),
  `docs/MEASUREMENT.md` (what has been measured about this tool and what has not), and
  `docs/COMPLIANCE.md` (the compliance posture and every refusal, including the seventeen that are enforced
  in code).
- `CONTRIBUTING.md` names which documentation layer a new claim or refusal belongs in, because the answer
  used to be "the README" and now it is not.

### Note on a filename

The quickstart is `docs/QUICKSTART.md` rather than the getting-started name it wanted, because that name is
already a `detect_paths` entry for `build.dev-setup` under `docs/`. On a case-insensitive filesystem
`locate()` resolved the catalog's lowercase candidate against a differently-cased file on disk, adopted the
page as this repository's development setup document, and emitted that lowercase path into `llms.txt`, where
it would have been a broken link on Linux. The underlying case sensitivity in `locate()` is not fixed here.

## [1.2.0] - 2026-08-05

Compliance. The catalog grows from 60 entries to 96, and for the first time it carries documents docdna refuses to write.

### Added

- **Seventeen `producible: R` entries**, the legal and regulator-facing instruments: HIPAA security risk assessment and business associate agreement, SOC 2 system description, PCI self-assessment, System Security Plan and authority to operate, the impact assessment family, the CRA technical file and EU declaration of conformity, AI Act Annex IV and GPAI documentation, the accessibility conformance report and statement, secure design review, penetration test and training records. R was in the schema since 1.0.0 and had never had a row, so `docdna_backfill.py`'s refusal branch, invariant I1 and invariant I6 were all dead code. They are live now.
- **`refusal_reason` and `signed_by` on every R entry**, printed verbatim when a user asks for the document. The old refusal said "a qualified human drafts it and signs it"; it now says who. Ask for the HIPAA risk assessment and it names the covered entity's Security Official, and says docdna writes the inventory that feeds it and refuses the assessment itself.
- Twenty manifest-only rows covering the SOC 2 criteria a codebase can be measured against, among them identity lifecycle (CC6.2), audit logging (CC7.2) and hardening baseline (CC6.6), plus the GDPR, HIPAA and PCI rows that share those artifacts through `satisfies` rather than duplicating them.
- `assure.phi-inventory`, writable, because an inventory of where health data sits is derivable from a schema and is the honest input to an assessment docdna will not write.
- Five overlays that had been deferred: health, payments, regulated, safety-critical, app-store.
- Six `skill/references/regime-facts/*.md` files carrying `verified:` dates, with 47 facts checked against primary sources: eCFR, the AICPA, the PCI SSC, EUR-Lex, NIST, and the Canadian Centre for Cyber Security. Three facts could not be confirmed and sit in an explicit "Unverified, do not rely on" section rather than in the body: the ITSG-33 Annex 1 data-classification anchor, the AIA level-to-requirement matrix in Appendix C, and the NIST AI RMF catalog facts whose endpoint would not open. Vendor summaries, law-firm explainers and third-party mappings hosted by NIST were all rejected as non-primary.
- `tests/fixtures/health_service` and `tests/fixtures/payments_service`, so the compliance selection is regression-tested rather than argued about.

### Fixed

- **An excluded directory now leaves the signal index, not only the document and drift passes.** A repository that vendors another project under `fixtures/` or `examples/` had that project's manifests read as its own. One demo depending on `fhirclient` made this repository report a health overlay and state that card data crossed it. A repository could have been told it was a HIPAA covered entity because a sample app pulled in an SDK.
- Ten new rows gated a legal instrument on a jurisdiction signal, and the validator refused all ten: a hint may open a question, it may never set a verdict. A stray `eu-west-1` in a Terraform file must not make a GDPR processing record required. They gate on the markets answer instead.

### Changed

- An R entry selects at `optional` and no higher. Only an interview answer raises one to `required` (invariant I6), because a grep that finds an IAM role must not make a System Security Plan required.

## [1.1.0] - 2026-08-01

Drift was released as the flagship on the strength of runs against the eight fixture repositories and this one. It was never measured. This release is what five rounds of measurement did to it.

Round four ran the tool against five repositories it had never seen and adjudicated all 46 path findings by hand, one at a time, against the tree they came from. Five were real: 10.9 percent. Path drift was demoted and command drift took the headline, on the argument that a command either is or is not declared in the manifest nearest the document, so the question was decidable.

Round five measured that argument. Fifty-one repositories, every finding adjudicated by hand, none sampled. `command-not-found` produced 31 findings and 1 was real drift: 3.2 percent. Of the 27 rows it rated HIGH confidence, 0 were real. Recall is the other half of the picture and it is worse: across 77 documented commands in 5 maintained repositories, not one had a missing script name. The base rate of the defect this pass hunts is approximately zero. And 28 of the 30 command false positives were documents making no claim about the repository at all: comparison tables with metasyntactic placeholders, task templates, case studies about other people's repositories, and one hypothetical drift example inside an instruction about detecting drift. The question is not decidable, because the string in the document was never a claim about this tree. Volume ran the same way: across all 51 repositories, drift output was 93.6 percent path rows and 6.4 percent command rows.

So neither drift pass is a headline feature. Both are leads, both ship with their measured precision printed next to them, and the README now leads with the selection engine: deciding which documents a repository owes, naming which it does not owe and why, and expiring those exclusions with tripwires. That claim ships qualitatively, with no percentage, because selection has never been adjudicated either. What is known about it, and what is not, is written into the README rather than left for round six to discover.

### Fixed: eight overclaims docdna made about itself

An independent ship gate read this project's own documentation the way this project reads everybody else's, and found eight places where docdna asserted something its own repository could not prove. Every one is the project's single rule broken about itself, which is the only kind of failure here that costs more than the feature it describes: a tool that overstates its own behaviour has no standing to report anybody else's drift. All eight were corrected toward the code, and the code was corrected only where the code was the thing that was wrong.

- **`skill/SKILL.md` told the agent to print findings under a `WRONG NOW` heading that 1.1.0 retired.** `docdna_select.py` has no such heading, all three drift kinds render under `POSSIBLE STALE REFERENCES`, and `tests/test_select.py` asserts the string is absent from every report. The instruction now describes the renderer that exists, and says why the heading was retired rather than reserved.
- **`skill/SKILL.md` documented the report order wrongly.** It listed drift second. `render_report` emits the owed set, then what is not applicable, then the boundary note, then the assumptions, then the leads, then `NEXT`, so drift is fifth of six and second to last. `tests/test_select.py` has pinned that order all along. The documented order now matches it.
- **`docdna_llms.py` shipped the word "contradicted" into every generated `llms.txt`.** The `present-drifted` note read "Stale: at least one claim in it is contradicted by the code." A document earns `present-drifted` from any single `confidence: low` lead, and the two passes behind that state adjudicate at 3.2 and 10.9 percent precision, so the word asserted a verdict the row does not carry. The note now describes a lead that did not resolve and is for a human to read. This is a code change, and `llms.txt` was regenerated from it.
- **`README.md` said "It will tell you the code contradicts the document."** It does not. Every drift row is `confidence: low`, and `skill/SKILL.md` forbids that framing four sections earlier. The bullet now reads as non-goal 1 already did: it reports where code and document disagree.
- **The "What a first run looks like" sample in `README.md` was written by hand and was not what the renderer prints.** It showed a `Drift` label and the word `confirmed`, neither of which appears anywhere in `docdna_select.py`, whose `LEAD_LABEL` is `Leads` and whose empty-case text is "none across your N documents"; it printed "none confirmed" directly above nine stale references; and it put `POSSIBLE STALE REFERENCES` second where the renderer puts it second to last. A fabricated sample in the README of a tool whose thesis is derived-from-the-code is the sharpest own goal available. The sample is now stdout from `docdna_select.py`, pasted unedited, and the README gives the two-command recipe that reproduces it against `tests/fixtures/internal_service`, the repository the fake sample had been dressing up. Generating it against this repository was tried first and rejected on the output rather than on the principle: pasting real rows into `README.md` puts the counted nouns from those rows into the page, the count pass then reads them back as claims this repository makes about its own routing table, and the top three leads converge on the sample quoting itself. That is a true report and a useless illustration.
- **`README.md` claimed the enforced Definition of Done is derivable from branch protection and required reviewers.** This project's own template refutes it: `skill/templates/verify-dod.md` says branch protection lives on the forge and docdna cannot see it unless a committed settings file declares it. No `branch_protection` or required-review signal exists among the 132. The claim is narrowed to what `signals.json` observes, which is `deploy.ci`, `proc.pr_template` and `proc.codeowners`, with the forge settings named as the `unverifiable` GAP they are.
- **Two different measurements were merged into one corpus.** `skill/SKILL.md` and `docdna_select.py` both said `path-not-found` was measured "on 51 repositories". It was not. The 5 of 46 path adjudication was a five-repository holdout, as `README.md` and this file say correctly a few paragraphs up; only the command measurement covered 51. The two are separated everywhere they are stated.
- **"No tripwire has yet been observed firing on a real repository" was literally true and read as false.** Running `docdna_check.py` on this repository prints `TRIPWIRES FIRING (1)`, `govern.ownership`, now true on `users.is_oss` and `q1_users`. The qualifier "over real elapsed time" survived the contradiction; a reader watching the tool print the opposite of the sentence would not stay to parse it. Both files now state what is true: firing is observed and correct on a first evaluation, and what remains unobserved is a predicate flipping from false to true across real elapsed time as a repository changes, which is the temporal claim the feature actually rests on.

### Fixed: six more overclaims, and the test that stops the samples drifting again

A second independent gate read the corrected documentation and found six more, three of them blocking. The pattern in all six is the same one the first gate found: a rule stated as an absolute where the code holds it with an exception, or a number published without the run that produced it. Every one is corrected toward the code.

- **"Every selected document names the signal that selected it, with a file path" was false, in `README.md` and in `skill/SKILL.md`.** On this repository's own manifest 13 of the 48 selected rows carry `evidence: []` and name no signal. `govern.manifest` is `required` and says only that the catalog selects it for every repository; `verify.dod` is `recommended` and cites `q1_users=public`, which is an interview answer and not a signal, and has no path either. The README printed `govern.manifest` with no path in its own verified sample fifty-six lines below the claim. `skill/SKILL.md` made it worse by adding a consequent, "a document that cannot name what selected it is not required", which is backwards for exactly those rows: they cannot name a signal and they are required. Both sites now state the four cases the selector actually produces. A document selected by a signal cites it with the file that carries it. A document selected by the catalog baseline, by an interview answer, or by a signal's absence says which, and has no file path, because none of the three is a place in the code. `skill/SKILL.md` also tells the model to read the row's `evidence` before promising a user a path.
- **"docdna is read-only and executes nothing" was false in both halves, in `README.md` and in `skill/SKILL.md`.** It writes `.docdna/manifest.json`, `DOCDNA.md`, `llms.txt`, `docs/**` and the agent instruction files, which the README's own Three modes table says two paragraphs earlier, and `docdna_select.py` spawns `docdna_scan.py` through `subprocess.run`. The load-bearing point was never the absolute and survives it: docdna does not run the documented repository's own commands, which is the whole reason a `run:` citation is self-attested and reported as SELF-ATTESTED, NOT VERIFIED. Non-goal 7 already carried the true phrasing, "does not run tests, scanners, the application, or anything on the network", and both sites now say that instead. Two places keep the old wording on purpose: `skill/references/evidence.md`, which is outside this change, and the 1.0.0 entry below, which is a record of what shipped then and is not rewritten after the fact.
- **The `not looked at, or refused` block in `README.md` was real stdout with two of its eight family rows deleted, and the sentence above it did not describe the rows that remained.** The block is regenerated whole. The sentence claimed every unknown is printed "with the question that would resolve it", which is not true of the `a11y`, `ai` and `sec` rows: they read `gate did not fire` and name no question at all. It now separates the two shapes. A family the scanner refused to guess at names the question to ask; a family whose gate never fired sometimes names a resolving question and sometimes names none, because a pass that never ran can leave nothing to ask about. Chasing that number turned up one more: `skill/SKILL.md` told the model that the `ASSUMED` section carries the count of signals whose gate did not fire, and `render_report` puts nothing there but the assumed answers and their blast radius. The unknown counts come from `docdna_scan.py` and the skill now says so, because an instruction to print a number the renderer does not emit is an instruction to invent one.
- **The path pass drops less than `README.md` and `skill/SKILL.md` said it drops.** Both said a reference whose parent directory does not exist is dropped. The gate in `docdna_scan.py` drops only when the parent directory and the first path component are both missing, so a reference under a directory that does not exist inside `skill/` is still reported, because `skill/` itself is there. The consequence that motivated the sentence is unchanged, since deleting the whole `docs/` tree removes both, and the rule statement is narrowed to the condition the code tests.
- **The exit code table in `skill/SKILL.md` was presented as exhaustive and missed two cases.** `docdna_backfill.py --verify` returns 1 when the report is not ok, which the table did not mention at all, and `docdna_wire.py` cannot return 2 because its `main` returns `None` and is never wrapped in `sys.exit`. The same is true of `docdna_scan.py`, which exits 0 even when pointed at a directory that does not exist. Both are now named as helpers that report no status of their own, so a caller does not read their 0 as success.
- **"35 come back `unknown, gate did not fire`" was published as a median with no run behind it.** The measured section publishes present-signal figures only: 4 to 46 across 51 repositories, median 19. Nothing was ever measured for the unknown count across a corpus. The number is gone from `README.md` and from `skill/SKILL.md`, and the skill now tells the model to quote the run in front of it rather than a median. An unattributed number is the thing this release exists to stop, and shipping one inside the paragraph that says so is the version of the mistake that costs the most.

### Fixed: three more, found by the release gate

A third independent gate read the corrected documentation against the code rather than against the diff, and found three more. Two are the same shape as the eight and the six: an absolute stated where the code holds an exception. The third is the opposite mistake, a check described as looser than it now is, which buys no false confidence but is still a claim the repository refutes.

- **`skill/SKILL.md` called Survey "a pure function of the scan plus the catalog, so re-running it is free and idempotent."** It is neither. `docdna_select.py` calls `read_prior`, carries the previous coverage into `manifest["previous"]`, and renders "(was 0 of 20 on <date>)" from it, so the output depends on the last run as well as on the scan. `DOCDNA.md` is itself a document the next scan inventories, so run two adopts it and reports one fewer missing document than run one. The CI convergence gate has said so in a comment all along: the first two runs legitimately differ and the bytes settle from run three. Telling the model a re-run changes nothing is telling it to contradict what the user is about to see. The skill now states the delta behaviour, names run three as the settling point, and forbids the word.
- **The Three modes table in `README.md` said Check writes "Nothing."** `docdna_check.py` regenerates the open-gaps block inside `DOCDNA.md` whenever the gaps pass finds a gap, which is why it carries a `--no-write` flag whose help text reads "never touch `DOCDNA.md`, even when the gaps pass runs", and why `skill/SKILL.md` documents that flag. Run Check on `tests/fixtures/documented_repo` and it prints "written: ## Open gaps regenerated in DOCDNA.md". The table is the same one this file cites two entries above as the refutation of "docdna is read-only and executes nothing", so it was refuting a claim while making a smaller version of it. The cell now names what is written and the flag that stops it.
- **`CONTRIBUTING.md` described the verifier's number rule as it stood before proximity binding**, saying `--verify` "accepts any number that appears anywhere in that file, not only beside the anchor". Both tools now bind a number to the `BIND_LINES` lines around the place the citation names. The real bypass is narrower and still worth writing down: a number inside that window is accepted whether or not the anchor says anything about it. The same bullet list also carried the third live copy of "docdna is read-only", which the entry two above says was kept in two places on purpose. `CONTRIBUTING.md` was not one of them, and it now says what non-goal 7 says.

### Added: the samples are checked mechanically now

- **`tests/test_readme_samples.py` regenerates every documented sample of tool output and compares it byte for byte.** A fenced block counts as tool output only when the line above it carries a marker naming exactly how to regenerate it, `TARGET` is substituted with a throwaway copy of the named repository so a command that writes a manifest never touches the tree under test, and the comparison has no normalisation, no subset matching and no tolerance, because the defect being prevented is a deleted row and a subset match is what a deleted row looks like. An optional `section="<header>"` narrows the comparison to one blank-line-delimited section, taken from its header to the blank line that closes it, so a row cannot be dropped off the end of one either. An unmarked fence is prose and is skipped, which is how a reader-typed shell command sits in the same page, with one exception: an unmarked fence may not carry a line either renderer emits as a section header, because that is a fabricated sample wearing a disguise. Seven consecutive review rounds shipped a hand-edited block of tool output in `README.md`; human reading is not the control that catches that, so the control is mechanical. It adds 20 tests, taking the suite to 319.

### Removed

- **The `[build-system]` rule, because it was factually false.** `command_surface` read a `pyproject.toml` with no `[build-system]` table as a broken editable install and emitted a `command-not-found` row against `pip install -e .`. Checked on 2026-08-01 against a real virtualenv holding pip 25.3 and nothing else: on a tree whose `pyproject.toml` declares `[project]` and no `[build-system]`, `pip install -e ".[dev]" --no-deps` exits 0 and the package imports. PEP 517 falls back to `setuptools.build_meta:__legacy__` for exactly this shape, so the absence of the table is ordinary and there was nothing to report. The rule, its constant, and the finding are gone, and a test asserts that neither attribute exists rather than that the row is suppressed. This is the only claim in the project that was disproved by running the thing it described.

### Fixed

- **A command was checked against whichever manifest the walk reached first, not the one nearest the document.** `command_surface` kept a single `scripts_path` and a single `makefile` and ignored every later `package.json` or `Makefile` it found, so in any monorepo a `npm run dev` in `services/api/README.md` was resolved against the root `package.json`, or against a sibling package's, depending only on walk order. Both the false positive and the false negative it produced were silent. npm and make manifests are now keyed by directory, as the Python ones already were, every check resolves through the chain of manifests from the document's own folder upward, and a command declared elsewhere in the tree yields a row naming where it actually lives, at low confidence, rather than an assertion that it does not. This is the fix that makes `command-not-found` correct on monorepos. It removed a class of silent false positives and false negatives; round five then showed that it did not make the pass reliable, because the failures that remain are about what the sentence meant, not about which manifest was read.
- **Path token extraction read things that were not references, and missed things that were.** A fragment anchor was taken as part of the filename, so `lib/profiles.js#listPacks` was reported missing under that whole string. A call expression such as `lib/pillars.init(projectRoot)` was treated as a path. An extension-less module reference resolved against nothing, so `lib/profiles` was reported missing with `lib/profiles.js` or `lib/profiles/index.js` sitting on disk, and a directory written with a trailing slash was discarded before it could be checked at all. Fragments are now stripped before resolution, expression characters reject the token outright, module and member-access resolution try the real extensions and index stems, and a trailing slash is what makes an extension-less token a reference. Over the 46 adjudicated findings the extractor produced no token that was not a genuine path reference in the document, which is what leaves the remaining failures semantic.
- **`skill/SKILL.md` claimed twenty `producible: M` entries where the catalog carries nineteen**, which is the count the README and the 1.0.0 entry have always given. A skill whose one rule is that nothing is asserted the repository cannot prove does not get to miscount its own catalog.
- **A path correctly named as history or as an absence was reported as drift.** A line saying that a file moved, was renamed, or no longer exists is not a claim that the path is there. Relocation and denied presence are now read from the sentence around the token. A path that is present on disk but gitignored is no longer reported either, with `git check-ignore` as the authority and any fallback declared in the scan output rather than applied quietly.

### Changed

- **Two claims were removed from the README because measurement falsified them.** "Command drift is the real feature" and the claim that whether a documented command is declared is a "decidable" question are both gone, and neither was replaced with a smaller version of itself. Nothing on that page now describes either drift pass as more than a lead.
- **The README leads with the selection engine instead**, which is the one thing here that nothing else does: linters, doc generators and link checkers all check what already exists, and none of them decides what should exist and then defends the absence. It ships with no percentage attached, and with a section saying so. What exists for it is that across 51 repositories the signal layer discriminated strongly and never errored, with present signals per repository ranging from 4 to 46 and a median of 19, so the inputs to selection genuinely vary by repository rather than emitting a constant list. What does not exist is anybody's judgment of whether the selected set is correct for any repository: no ground truth, no adjudicated sample, no measurement of agreement with a human, no check on the exclusion reasons, and no tripwire ever observed firing on a real repository over real elapsed time.
- **The README states the assumption load rather than implying there is none.** The registry holds 132 signals, and across the 51 repositories measured the count coming back present ranged from 4 to 46 with a median of 19. How many come back `unknown` was never measured across a corpus, so no median for it is published. So the honest description is not that docdna decides your documentation set; it decides what the code can settle and shows you what it assumed about the rest. The scanner's `not looked at, or refused` block is printed in the README as part of the pitch.
- **Both drift passes are demoted, and both measured numbers are published rather than buried.** 3.2 percent for commands, over 31 findings on 51 repositories, with 0 of 27 HIGH-confidence rows true and recall approximately zero because the defect barely occurs; 10.9 percent for paths, over 46 findings on 5. One line carries the reason for both: a document names a command or a path for many reasons and only one of them is a claim about this repository right now. The specifics are there too, that 28 of 30 command false positives were documents making no claim about the repository at all, and that on the path side 16 were install targets in a host capability matrix, 10 were CHANGELOG entries describing the tree as it was, and the rest were prospective paths, cross-repository references, hypothetical examples, and reports of deliberate deletions. Every one of those paths is correctly absent, and no test that asks whether a string is a file on disk can tell them apart. Saying this in the README is cheaper than having a user discover it on their own repository.
- **Every drift row now emits at `confidence: low` with a `precision_note`, commands as well as paths.** The command pass used to rate a row HIGH when the name was declared in no manifest in the chain, which is exactly the population that measured 0 true of 27. In `docdna_check.py` that makes every drift row a minor finding. Gating is otherwise unchanged: drift of any kind gates CI only for the documents named in `assurance_set`.
- **Command details were rewritten from consequence to observation.** A detail used to say what would break; it now says what was read and stops. A test compiles the vocabulary of consequence the removed `[build-system]` detail was written in, fails, breaks, error, cannot, would, should, and asserts that no command detail matches it, over a tree that fires the node, make, python, cargo, go and process rules at once.
- **The report order in `skill/SKILL.md` puts selection first.** `MISSING AND LOAD-BEARING` leads, drift follows as leads subordinate to it, then `NOT APPLICABLE`, `ASSUMED` with the count of signals whose gate did not fire, then `NEXT`. Path rows stay under `POSSIBLE STALE REFERENCES` with a pointer to `.docdna/manifest.json` rather than a per-row list, no report opens with a count of documents that "contradict the code", and the sample run in `README.md` is the current report shape rather than an older one.
- **The scan reports what the path pass threw away.** The recall gates are counted by reason in `scan.drift.discarded`, and the text output prints how many of the candidates were dropped, because a check that discards more candidates than it reports is a filtered view and should not be read as a complete one. On this repository the gates drop several times more candidates than the report carries.

### Still unmeasured

Stated here so the next round starts from a list rather than from a surprise.

- **Selection has never been adjudicated.** Nobody has judged whether the set of documents docdna selects is correct for any repository. There is no ground truth, no adjudicated sample, and no measurement of agreement with a human. The signal layer under it was exercised on 51 repositories without erroring and discriminates strongly between repositories; that is a necessary condition for selection to mean something, not evidence that it is right.
- **Exclusion reasons are unchecked.** The mechanism that requires every exclusion to carry a reason, a citation, and a tripwire is enforced and tested. The reasons themselves have never been read for soundness.
- **No tripwire has been observed flipping across real elapsed time.** Firing itself is observed and correct: `docdna_check.py` on this repository reports `govern.ownership` firing, now true on `users.is_oss` and `q1_users`. Every firing seen so far, here and in the tests, is a first evaluation, where the predicate was already true when it was first checked. The temporal case the feature rests on, an exclusion written while its predicate was false and a later run catching it after the repository changed, has no field record. `README.md` and `skill/SKILL.md` state that narrower claim at the point where they tell the model to lead with tripwires.
- **The `count-mismatch` and `stale-vs-code` checks have not been adjudicated.** They are reported as leads alongside the path rows and will keep that standing until somebody measures them.
- **A reference whose parent directory and whose first path component are both absent is dropped, not reported.** Either one is enough to keep it, so a reference to a file under a directory that does not exist inside `skill/` is still reported, because `skill/` itself is there. When no part of the path is rooted here there is nothing to distinguish a stale document from a path that was never rooted in this repository, so the check declines to guess. The cost is that deleting an entire `docs/` directory makes every reference into it invisible rather than glaring, which is the one path failure mode a reader would most expect to be caught. The drop is counted under `first_component_not_a_directory`, and the limitation is stated in `README.md` and in `skill/SKILL.md` rather than left to be found.

### Added

- Fixture repositories for a monorepo and for gitignored paths, and a drift suite covering the manifest chain, the token rules, the historical-mention rules, the editable-install case that disproved the `[build-system]` rule, and the vocabulary check that keeps a command detail from asserting a consequence. With the sample regeneration tests below, the suite is 319 tests over 10 fixture repositories, up from 232 over 8 at 1.0.0.

## [1.0.1] - 2026-08-01

### Fixed

- **`docdna_wire.py` could delete another tool's instruction block outright.** `replace_block` located the span to overwrite with two independent `text.find()` calls, so the span was `[first start marker, first end marker]`, which is not necessarily one block. Given a duplicated docdna start marker with a codedna block between the two, or a docdna block that had come to enclose a codedna block after a hand-edit or a bad merge, that span reached across the sibling block and replacing it erased that block's content and both of its markers. The nine existing wiring tests all used the healthy side-by-side layout and none of them could see it. `locate_block` now anchors the end search after the start, re-anchors on a nested start rather than spanning it, and refuses any span containing a marker that is not docdna's own. A file in that state is reported as `skipped` and left byte-identical, with the reason printed, because a duplicate block is recoverable and deleted content is not.

### Changed

- `docdna_wire.py` now carries a `VERSION` constant like the other five helpers.

## [1.0.0] - 2026-08-01

First public release. Point docdna at a repository and it answers three questions from the code: which documents this project owes, which of the ones it already has are now false, and which of those the code can write without asking anyone. It is a portable coding-agent skill with no service, no account, no build step, and no dependency beyond Python 3.8.

Nothing before this was released, so there is nothing here to correct. The reasoning that produced the shape below, including the arguments that were lost, is recorded in [`docs/design/`](docs/design/).

### Added

- **Survey**, the default mode and the only one that needs nothing to run. `docdna_scan.py` is a stdlib-only scanner: it builds a path index that keeps `.github/` and the other high-signal dot directories, honours `.gitignore` when git is present, refuses to read `.env`, indexes `.docx` and `.pdf` without parsing them, and runs the signal registry in three gated passes. `docdna_select.py` turns that scan plus the catalog into `.docdna/manifest.json` and the one-screen `DOCDNA.md`, as a pure function of its inputs, so re-running it is free.
- **Zero questions on the first run.** Every interview answer is defaulted from signals, labelled `assumed`, and printed with what changes if it is wrong. The user corrects one in a sentence with `docdna_select.py --answer`, and every later run inherits the answer.
- **Four drift checks that work on documentation docdna has never touched**, needing no frontmatter, no adoption, and no prior run: command strings against `package.json` scripts, `Makefile` targets, CI steps, and `pyproject` entry points; paths named in documents, for existence; claimed endpoint counts against detected routes; and a document's last commit against the last commit of the code it names. Every report leads with drift, because a document the code proves false is concrete and undeniable and a missing document is abstract and arguable.
- **Backfill**, `docdna_backfill.py`, which writes the derivable ten from code evidence with citations, GAP markers, lifecycle frontmatter, and a reconstruction banner saying the document is derived rather than reviewed. Runs are capped at five documents, estimated before they start, and resumable from `write_status` in the manifest, because an interrupted long run that loses its manifest degrades into exactly the confident fiction the tool exists to prevent. `--verify` re-reads every citation against the code and deletes the claim rather than softening it, since a hedge still reads as documentation.
- **Check**, `docdna_check.py`, the CI gate. Six passes over one walk: drift, frontmatter lint, GAP rollup, traceability spine, tripwires, and orphans. Drift is a warning unless the document is named in `assurance_set` in `.docdna/config.json`, because a gate that turns everything red is a gate that gets switched off in week two.
- **Tripwires**, the pass that justifies re-running the tool at all. Every exclusion carries a `revisit_when` predicate, so a document correctly skipped last quarter reports itself the moment the signal that justified skipping it stops being true. Nothing else in the documentation world tells you this.
- **A 60-entry document catalog organized by lifecycle stage rather than by audience**, with a 132-signal registry, 88 verdict rules, eight archetypes, five overlays, and an eight-question interview. Forty-one entries are producible; the other nineteen are manifest-only, where the threat model, the runbook, and the data classification register live: docdna tracks the row, names the signal that made it required, and states what a human has to supply.
- **Absence of evidence is never encoded as false.** A detector that did not run reports `unknown`, and `unknown` never silences a document. That is the difference between "we decided this does not apply" and "we did not look", and it is the only reason the manifest is worth showing an assessor.
- **Ten hard invariants enforced in `docdna_select.py` at catalog load time rather than in prose**, so a catalog change that violates one fails the build instead of degrading quietly. They include the guardrail that no signal alone may make a legal instrument required, and a semantic check that refuses every path from a jurisdiction hint to a verdict rather than matching the syntax of one.
- **The evidence rules**: four citation classes, `code`, `run`, `ref`, and `human`, paired GAP syntax, and the rule the whole project hangs from, that no number is ever generated. A number is cited to the four lines around the place the citation names, in a file inside the repository under analysis, or it is a GAP a human owns. A citation naming a file and no place inside it binds nothing, a citation that leaves the repository is refused, a `run:` citation is reported as self-attested because docdna executes nothing, and a `human:` one is recorded as an attestation rather than a verification. The limits of the check are published beside the check, in the second section of `skill/references/evidence.md`.
- **Ten document templates** under `skill/templates/`, one per derivable document, plus the four normative partials `_frontmatter.md`, `_gap.md`, `_banner.md`, and `_document-control.md`. Four reference files load on demand: `evidence.md`, `selection.md`, `lifecycle.md`, and `antipatterns.md`.
- **`docdna_llms.py`**, which emits `llms.txt` and its sidecar at `.docdna/meta/build.llms-txt.yml` from the manifest, grouped by lifecycle stage. It indexes only what is present, says so when nothing in the profile requires an `llms.txt`, and states the precedence rule in the file: if a document contradicts the code, the code is correct.
- **`docdna_wire.py`**, which writes the docdna pointer block into `AGENTS.md` as the portable baseline and updates the tool-specific instruction files that already exist. Its markers and rule basenames are threaded through `replace_block` as parameters, which is what makes clobbering another tool's block in the same file structurally impossible rather than merely unlikely.
- **`install.sh` for Claude Code, Codex, Cursor, and Windsurf/Cascade.** It copies the whole `skill/` directory, because the catalog, references, and templates have to sit beside `SKILL.md`, and it removes a stale bare-file install if it finds one: a skill is a directory containing `SKILL.md`, and a file at `~/.claude/skills/docdna.md` is not loaded.
- **`exclude_dirs` in `.docdna/config.json`, and `--exclude-dir` on the scanner, the selector, and the checker.** A repository that vendors another repository under `tests/fixtures/` or `examples/` would otherwise have that repository's documentation read as its own, and its root-relative citations resolved against the wrong root.
- **A suite of 232 tests over 8 fixture repositories**, four of which exist only to hold false positives down: a client-side router is not a server route, a French locale is not weak crypto, a `Region` enum is not a jurisdiction, and a latitude is not personal data. Every runtime detection pattern ships with a negative fixture, not just a positive one.
- **CI that dogfoods the tool on itself.** It compiles every helper, validates the catalog JSON, runs the suite, runs the whole pipeline end to end on this repository, requires `docdna_check.py` to report zero fabricated-number findings against docdna's own documentation, asserts that Survey converges, shellchecks the installer, and installs the skill and runs it from the installed location. docdna's own documentation is the one corpus whose every claim can be adjudicated by hand, and it is full of the shapes a number rule gets wrong.
