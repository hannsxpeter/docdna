## Launch Surface

The launch surface is the repository README plus the GitHub release page discovered from the verified
remote. There is no deployed application, website, staging origin, signup flow, or custom web metadata
surface.

Landing-page implementation is Not Applicable. The README already supplies the evergreen hero, audience,
specific value proposition, differentiator, installation path, real output, and proof boundary. Its central
claim is substitution-tested: replacing DocDNA with a generic documentation tool breaks the promise to rule
documents in or out from repository evidence, cite every generated claim, and mark every unresolved claim as
a gap.

A custom OG card is Not Applicable. No owned web page or image metadata surface exists to receive or render
one, and the release is not claiming a custom social preview. GitHub owns the rendering of its repository and
release pages. The release owner must not record an OG render or card-debugger pass for this release.

The public release body is `.godpowers/launch/RELEASE-NOTES-1.4.0.md`. It uses product-specific claims from
the changelog and README, separates the three release values, includes the immutable tag install command,
and discloses the installed-byte and installer rollback limits from the Medium findings.

## Success Criteria

Launch is complete only when all of the following are true:

1. GitHub Actions passes the exact release commit on Python 3.8 and current Python, including registry JSON,
   registry-declared compilation, 527 tests, stable artifacts, ShellCheck, and the isolated installed
   consumer flows.
2. Immediately after every other readiness check, both prepublication commands return `verdict: pass` for
   the current hardening hash and timestamp.
3. Annotated tag `v1.4.0` resolves to the exact merged release commit and exists on `origin`.
4. The GitHub release exists for `v1.4.0`, uses the prepared notes, and reports a URL returned by GitHub.
5. A fresh temporary clone of `v1.4.0` installs the skill and passes installed Doctor, Proof, Status, packet,
   Check, llms, and Wire smoke checks.
6. Local `main` equals `origin/main`, and the final worktree is clean after release-evidence closure.

No adoption count is invented. At D+1 and D+7, record GitHub release availability, issue reports, and any
available repository traffic without treating absent provider data as zero usage.

## Exact Activation Sequence

After the candidate is merged, run from the repository root. Stop at the first failure.

```sh
git checkout main
git pull --ff-only origin main
git status --short
release_commit=$(git rev-parse main)
gh run list --workflow CI --commit "$release_commit"
```

Confirm the exact-commit run passed both matrix jobs. Do not substitute a branch-only or older green run.

```sh
node /Users/hprincivil/.codex/godpowers-runtime/lib/prepublication-gate.js --record --project=.
node /Users/hprincivil/.codex/godpowers-runtime/lib/prepublication-gate.js --check --project=.
```

Continue only when the second command returns `verdict: pass`. Any later hardening edit invalidates the
record and requires a fresh record and check.

With `main` clean and synchronized:

```sh
git tag -a v1.4.0 "$release_commit" -m "DocDNA 1.4.0"
git push origin v1.4.0
gh release create v1.4.0 --verify-tag --title "DocDNA 1.4.0" \
  --notes-file .godpowers/launch/RELEASE-NOTES-1.4.0.md
gh release view v1.4.0 --json url,tagName,targetCommitish,publishedAt
```

Then run the tagged-install smoke against the remote already verified above:

```sh
smoke_root=$(mktemp -d)
git clone --branch v1.4.0 --depth 1 https://github.com/hannsxpeter/docdna.git "$smoke_root/src"
skill_dest="$smoke_root/skills"
consumer_repo="$smoke_root/consumer"
CLAUDE_SKILLS_DIR="$skill_dest" "$smoke_root/src/install.sh" claude
cp -R "$smoke_root/src/tests/fixtures/internal_service" "$consumer_repo"
python3 "$skill_dest/docdna/scripts/docdna_doctor.py" --json
python3 "$skill_dest/docdna/scripts/docdna_proof.py" --json
python3 "$skill_dest/docdna/scripts/docdna_scan.py" --json "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_select.py" "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_status.py" --json "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_backfill.py" --only build.api-reference --json "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_check.py" "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_llms.py" "$consumer_repo" > /dev/null
python3 "$skill_dest/docdna/scripts/docdna_wire.py" --json "$consumer_repo" > /dev/null
```

Record the command and result in launch state. Finally verify:

```sh
git rev-parse main
git rev-parse origin/main
git rev-list -n 1 v1.4.0
git status --short
```

## Rollback

Before publication, any CI, smoke, or prepublication failure stops the sequence. Do not create or push the
tag.

After publication, a tagged-install failure, release-commit mismatch, or new Critical security finding
triggers withdrawal of launch announcements and a prominent GitHub issue or release warning. Preserve the
immutable `v1.4.0` tag and failed evidence, stop recommending that version, fix forward as `1.4.1`, rerun
hardening, CI, the installed-consumer smoke, and a fresh prepublication gate, then publish the patch. Do not
move or reuse `v1.4.0`.
