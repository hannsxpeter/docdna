# Build Plan: Delivery Increment 1.4.0 Trust Runtime

## Planning basis and gate exception

The root agent accepted a bounded-increment gate exception because `.godpowers/roadmap/ROADMAP.mdx`
and `.godpowers/stack/DECISION.mdx` do not exist. No current architecture artifact exists either. This
plan is grounded in the repository as it stands: a Python 3.8-compatible, standard-library CLI and
agent skill, POSIX filesystem safety, `unittest`, a shell installer, and GitHub Actions CI. The accepted
baseline is 429 passing tests.

The following trace IDs are local to this bounded increment because no canonical roadmap or PRD defines
them:

| Requirement | Bounded behavior |
| --- | --- |
| `P-MUST-01` | Prose review preserves protected Markdown spans and reports only visible prose findings. |
| `P-MUST-02` | Verification exposes stable, fixture-backed proof evidence and distinguishes verified, attested, self-attested, and refused evidence. |
| `P-MUST-03` | A consumer can run one doctor command against a unified runtime registry and receive a deterministic health verdict. |
| `P-MUST-04` | A fresh agent context receives a complete backfill packet, while status inspection returns one next action without writing. |
| `P-MUST-05` | Versioned docs, CI, installation, and an isolated consumer check prove the 1.4.0 release surface. |

## Wave map

| Wave | Parallel slices | Reason |
| --- | --- | --- |
| 1 | A, B | The slices own disjoint implementation, test, fixture, and catalog files. |
| 2 | C, D | C creates the doctor and runtime registry. D changes backfill planning and status. They share no owned files and depend separately on B and A. |
| 3 | E | Release integration consumes every earlier slice and owns the shared docs, version, generated-artifact, installer, and CI surfaces. |

No two slices in one wave modify the same path. A slice is one atomic implementation commit after its
tests pass. Wave 3 begins only after both Wave 2 slices pass review.

## Increment completion gate

The delivery increment is complete only when all five slices satisfy their acceptance criteria, every
focused suite passes on Python 3.8 and current Python, full discovery preserves the 429-test baseline and
includes all named new tests, the installed consumer flow passes from copied release bytes, generated
artifacts are stable, and `git diff --check` reports no whitespace errors. No implementation slice may
waive a failed proof, doctor, read-only, source-containment, or protected-span check to make the release
green.
